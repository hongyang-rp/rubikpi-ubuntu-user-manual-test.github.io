🧪 运行预置示例应用程序

🎯 开发者目标​

  • 快速体验开箱即用的功能，涵盖多种使用场景和设备能力
  • 在 Ubuntu 上使用 Qualcomm Intelligent Multimedia Product (QIMP) SDK 运行示例应用程序。

👤 用户画像​

  • 对人工智能感兴趣，正在探索多媒体功能的开发者或应用工程师

✅ 前提条件​

目标设备​

  • 需刷入 Ubuntu 操作系统
  • 在 Ubuntu 系统中安装 QIMP SDK - 参考流程#2
  • 具备适当权限的 终端访问 能力

💡 提示： 启动示例应用前，请确保系统已满足所有先决条件，以确保体验过程顺畅无阻。

操作步骤​

🛠️ 步骤 1：下载并运行脚本​

该脚本将自动获取示例应用程序所需的所有资源，包括：

  • 模型文件
  • 配置文件
  • 标签文件
  • 媒体文件

📦 脚本详情​

cd /home/ubuntu 
curl -L -O https://raw.githubusercontent.com/quic/sample-apps-for-qualcomm-linux/refs/heads/main/download_artifacts.sh
chmod +x download_artifacts.sh 
sudo -i 
cd /home/ubuntu 
./download_artifacts.sh -v GA1.4-rel -c QCS6490

📘 释义​

  • download_artifacts.sh 脚本可自动下载示例应用程序所需的所有资源：
  • 使用 -v 参数指定想要的版本（例如：GA1.4-rel）。
  • 使用 -c 参数指定设备芯片组 (例如：QCS6490)。

💡 提示： 运行脚本前，请确保终端具有相应权限，且开发环境符合 SDK 文档要求。

🧾 步骤 2：验证模型与标签文件​

在启动任何示例应用程序前，请确保以下必要文件已就位：

✅ 检查以下目录：​

  • 模型文件 → /etc/models/
  • 标签文件 → /etc/labels/

📌 注意： 这些文件是AI与多媒体应用程序正常运行的关键。若文件缺失，请重新运行资源下载脚本或检查SDK安装。

⚙️ 步骤 3：设置环境变量（如需要）​

部分示例应用程序需配置特定环境变量以确保显示和运行行为正常：

export XDG_RUNTIME_DIR=/dev/socket/weston 
export WAYLAND_DISPLAY=wayland-1

💡 提示： 这些变量通常用于控制显示设置、硬件加速或运行时路径。正确配置可确保程序稳定运行。

📂 步骤 4：进入示例应用程序目录​

要启动示例应用程序，请先进入其所在目录：

  • /opt/
  • /home/ubuntu/sample-apps/

进入目标文件夹后，通过终端启动相应应用：

cd <QIMP_SDK_INSTALL_PATH>/samples/

💡 提示： 可使用 ls 命令查看可用应用程序列表，通过 ./<app_name> 直接运行。

🧾 步骤 5：准备 JSON 配置文件​

部分示例应用程序需依赖正确配置的 JSON 文件才能运行。

🔍 操作说明​

  • 根据模型及输入要求，定位或创建所需的 JSON 配置文件（例如： aic_batch_io.json）。
  • 编辑 /etc/configs/config_classification.json 文件以匹配您的使用场景：
    • 📷 摄像头输入
    • 📁 文件输入
    • 🌐 RTSP 流输入
    • ⚙️ R运行时选项

示例配置结构​

将 JSON 文件置于可访问目录，确保应用程序启动时可正确读取配置。

{ 
"inputs": [
 		{"name": "input_1", "file": "input1.bin"}, 
		{"name": "input_2", "file": "input2.bin"} 
         ] 
}

📌 说明： 为何需要配置 JSON 文件？ 多数 QIMP SDK 示例应用程序（尤其是使用 QNN/AIC 后端的应用）需通过 JSON 配置文件来指定模型参数、输入/输出文件、运行时选项。 参考 SDK 文档 中的示例模板和参数详解。 --

🧠 步骤 6：通过 JSON 配置文件运行示例应用程序​

使用终端启动示例应用程序，并加载 JSON 配置文件。

./ai_classification_sample --aic-batch-json-input <path_to_json_config>

📊 步骤 7：查看输出结果​

应用程序运行后，请通过以下方式查看结果： 终端输出：分类结果将直接显示在终端中 输出文件： 如果在 JSON 配置文件中进行了相应设置，结果也可能会保存到指定的输出文件中。

📁 附加信息

开发者指南（提示与最佳实践）：​

• 如果出现 GBM 错误：执行 echo 0 > /var/cache/display/gbm_dbg_cfg.txt
• 按下 CTRL + C 可在终端中停止正在运行的示例应用程序。

• 如果显示失败，请检查环境变量设置和 HDMI 连接是否正确。

• 请确保模型文件和标签文件存在，且路径设置正确。
• 若遇到显示错误，请确认 Wayland 服务正在运行，且环境变量已正确设置。
• 若遇到权限问题，可将根分区重新挂载为可读写： mount -o remount,rw /
• 查看帮助选项，请运行 gst-ai-classification –help

报错示例及解决方法：​

• “Invalid model file path”: 下载正确的模型文件并放置在 /etc/models/。
• “Could not unlink (errno=30)”: 将 /usr as read-write 目录重新挂载为可读写模式。

• “No such file or directory”: 检查安装情况及文件路径是否正确
• “Execution stuck at gst_deinit”: 请确保所有必要文件都已正确放置。

性能优化建议：​

• 使用适配你硬件的优化模型（如LiteRT, SNPE, QNN）。
• 在推理过程中监控 CPU/GPU/HTP 的使用情况。

• 若支持，建议使用批量推理和量化模型以获得最佳性能。

• 请参考 SDK 文档中的推荐流水线配置及故障排查建议
